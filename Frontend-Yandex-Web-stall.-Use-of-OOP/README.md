# README.md

## Web-ларёк — интернет-магазин для веб-разработчиков

Приложение интернет-магазина, в котором можно просматривать каталог товаров, добавлять товары в корзину и оформлять заказ в два шага.

---

## Используемый стек

* TypeScript
* HTML / SCSS
* Сборка проекта (из стартового набора)
* Архитектура: **MVP (Model–View–Presenter)**
* Взаимодействие между частями приложения: **EventEmitter (брокер событий)**
* Работа с сервером: REST API (fetch)

---

## Сборка и запуск проекта

### 1) Установка зависимостей

```bash
npm install
```

### 2) Настройка переменных окружения

В корне проекта нужно создать файл `.env` и добавить:

```env
API_ORIGIN=https://larek-api.nomoreparties.co
```

> Важно: ссылка указывается **без слеша в конце**.

### 3) Запуск проекта

```bash
npm run start
```

(или `npm run dev` — в зависимости от настроек стартера)

### 4) Сборка

```bash
npm run build
```

## Архитектура проекта

Проект реализован по паттерну **MVP**:

* **Model** — хранит состояние приложения и бизнес-логику (корзина, заказ).
* **View** — отвечает только за отображение интерфейса и генерацию событий.
* **Presenter** — связывает модели и представления, подписывается на события и управляет логикой приложения.

Связь между частями приложения осуществляется через **EventEmitter**, что позволяет избежать прямых зависимостей между View и Model.

## Базовые классы и их назначение

### EventEmitter (`components/base/events.ts`)

Обеспечивает работу событий:

* подписка на события
* отписка от событий
* генерация событий (`emit`)
* передача данных в обработчики

Используется как единый брокер событий между View, Model и Presenter.

---

### Api (`components/base/api.ts`)

Обёртка над `fetch`:

* выполнение GET/POST запросов
* обработка ответа сервера
* централизованная обработка ошибок

---

### View (`components/base/view.ts`)

Базовый класс для всех визуальных компонентов:

* хранение DOM-элемента компонента
* рендер данных
* вспомогательные методы (например: `toggleClass`)

## Компоненты приложения

### Модели (Model)

**CartModel.ts**

* хранит список товаров в корзине
* добавляет / удаляет товары
* очищает корзину
* считает итоговую сумму
* не допускает добавление одного товара дважды

**OrderModel.ts**

* хранит данные заказа:

  * способ оплаты
  * адрес доставки
  * email
  * телефон
  * список товаров
* отвечает за валидацию данных заказа по шагам

---

### Представления (View)

**ItemView.ts**

* отображает карточку товара в каталоге
* открывает модальное окно с деталями товара
* генерирует события покупки/удаления

**CartView.ts**

* отображает список товаров в корзине
* показывает итоговую сумму
* генерирует события удаления товара и перехода к оформлению

**FormView.ts**

* базовый класс для форм оформления заказа
* содержит методы:

  * чтение данных из полей
  * отображение ошибок
  * переключение активности кнопок

**ModalView.ts**

* открытие/закрытие модальных окон
* закрытие по:

  * клику вне окна
  * нажатию на крестик

**SuccessWindowView.ts**

* отображает сообщение об успешной оплате
* содержит кнопку закрытия модального окна

---

### Инфраструктура

**DataApi.ts**

* специализированный API-клиент для работы с сервером:

  * загрузка списка товаров
  * отправка заказа
* использует `Api` как базовый слой сетевых запросов

**utils/constants.ts**

* хранит константы приложения (тексты, настройки, классы, селекторы)

**utils/utils.ts**

* вспомогательные функции:

  * форматирование
  * простая валидация
  * обработка данных

## Типы данных (`src/types/index.ts`)

В проекте выделены типы данных для API и для внутреннего состояния приложения.

### Основные типы

**IItem**

* описание товара:

  * `id`
  * `description`
  * `image`
  * `title`
  * `category`
  * `price` (может быть `null`)

**ICartModel**

* интерфейс модели корзины:

  * `add()`
  * `remove()`
  * `clear()`
  * `total` — итоговая сумма

**IOrder**

* структура заказа:

  * товары
  * адрес
  * способ оплаты (`PaymentType`)
  * email
  * телефон

**IOrderModel**

* расширенная структура заказа:

  * хранит состояние заказа
  * хранит ошибки валидации
  * позволяет очищать данные после успешной покупки

**IEventEmitter**

* интерфейс событийной системы:

  * `on()`
  * `off()`
  * `emit()`

**PaymentType**

* перечисление способов оплаты:

  * `online`
  * `cash`

## Реализация процессов (логика приложения)

### Просмотр каталога и товара

1. Приложение запрашивает список товаров через `DataApi`.
2. `ItemView` отображает карточки товаров.
3. При клике на карточку открывается модальное окно с деталями товара.

---

### Добавление товара в корзину

* При нажатии на кнопку «Купить» товар добавляется в корзину.
* Один и тот же товар **не может быть добавлен дважды**.
* Если товар уже в корзине, интерфейс сообщает об этом:

  * кнопка блокируется или меняет текст на «Удалить».
* Если цена товара отсутствует (`price === null`), кнопка «Купить» всегда деактивирована.

---

### Оформление заказа (2 шага)

#### Шаг 1 — способ оплаты и адрес

Пользователь:

* выбирает способ оплаты
* вводит адрес доставки

Кнопка «Далее» активируется только если:

* выбран способ оплаты
* поле адреса не пустое

Если данные невалидны — пользователь видит текст ошибки.

---

#### Шаг 2 — контактные данные

Пользователь вводит:

* email
* телефон

Кнопка «Оплатить» активируется только если:

* оба поля не пустые

Если данные невалидны — пользователь видит текст ошибки.

---

### Успешная оплата

1. После нажатия «Оплатить» отправляется запрос на сервер.
2. После подтверждения успешного ответа:

   * корзина очищается
   * данные форм очищаются
3. Появляется модальное окно успешной оплаты.
4. Кнопка в окне успеха только закрывает модальное окно (других действий нет).

## Взаимодействие компонентов (пример)

1. Пользователь нажимает «Купить» на карточке товара.
2. `ItemView` генерирует событие через `EventEmitter`.
3. `index.ts` (Presenter) ловит событие и вызывает метод `CartModel.add()`.
4. `CartModel` обновляет состояние и генерирует событие изменения корзины.
5. `CartView` получает событие и перерисовывает корзину.

Аналогично обрабатываются:

* удаление товаров
* открытие/закрытие модалок
* переход по шагам оформления
* отправка заказа и очистка состояния
